# GPU粒子からの固定格子水面メッシュ生成

## 採用方式

最終的なゲーム用水面には、シミュレーション粒子を直接描画する方式ではなく、シミュレーション領域を覆う固定格子メッシュを使用する。

```text
GPU粒子と空間グリッド
  ↓
固定格子メッシュの各X-Z座標で近傍粒子を検索
  ↓
Poly6カーネルで流体深さを重み付き平均
  ↓
隣接頂点の水深差から法線を計算
  ↓
GraphicsBufferを頂点シェーダーから参照
  ↓
URP Lit水面として描画
```

シミュレーション粒子数と水面メッシュ解像度は独立させる。現在はX、Z方向ともに128頂点、合計16,384頂点を正式な初期設定とする。

## 水深補間

水面頂点位置を`x`、近傍流体粒子を`j`としたとき、描画用流体深さは次の重み付き平均で求める。

```text
h(x) = Σ h_j W_poly6(|x - x_j|²) / Σ W_poly6(|x - x_j|²)
```

境界粒子は壁を表し、描画対象の流体ではないため補間対象から除外する。近傍探索にはシミュレーションで構築済みの連続配列型空間グリッドを再利用する。

水深計算は`CalculateSurfaceVertexDepths`、法線計算は`CalculateSurfaceVertexNormals`で行う。すべての水深が確定する前に隣接頂点を読む競合を避けるため、二つのカーネルへ分けて順番にDispatchする。

## 法線計算

左右の頂点からX方向接線、前後の頂点からZ方向接線を作る。

```text
tangentX = (X方向距離, rightDepth - leftDepth, 0)
tangentZ = (0, forwardDepth - backDepth, Z方向距離)
normal   = normalize(cross(tangentZ, tangentX))
```

`Fluid Depth Height Scale`で描画時のY変位を拡大する場合は、頂点シェーダーで法線のX、Z成分にも同じ倍率を反映してから正規化する。

## GPU内での受け渡し

`SphSweGpuSurfaceVertex`は流体深さ1個と法線1個を保持する。

```text
float   FluidDepth = 4 bytes
Vector3 Normal     = 12 bytes
合計                = 16 bytes
```

Compute Shaderが書き込んだ`SurfaceVertexBuffer`を水面頂点シェーダーから直接参照する。通常の水面描画では`AsyncGPUReadback`を使用せず、GPUからCPUへの同期を発生させない。

固定格子MeshはCPU側で初期化時に一度だけ生成する。実行中はMeshのCPU頂点配列を更新せず、頂点シェーダーが`SV_VertexID`に対応する水深と法線を読み取って変位させる。

## 描画設定

- 水面解像度：`128 × 128`
- Shader：`SPH-SWE/GPU Fluid Surface`
- URP LitのPBRライティングを使用
- 旧GPU粒子ビルボードRendererは診断表示として保持し、通常表示では無効にする
- `Ground Height`と`Fluid Depth Height Scale`は目的球側の水面追従設定と一致させる

## 既知の課題

近傍流体粒子が一つも見つからない頂点は、現在`FluidDepth = 0`となる。そのため、粒子分布が疎になった場所では局所的なくぼみが表示される場合がある。

小さく滑らかな変形は粒子分布を反映したものとして当面許容する。固定された穴、鋭い三角形状のへこみ、目的球との表示高さの不一致が目立つ場合は、次の候補を検討する。

- 直前フレームの有効な水深を維持する
- 隣接する有効な水面頂点から穴埋めする
- 基準流体深さをフォールバックとして使用する

粘性係数は波の減衰だけでなく数値安定性にも寄与するため、この表示上の課題を解決する目的で大きく下げない。

## 参照実装との関係

参照実装も固定格子メッシュを持ち、粒子から求めた水面高さでMesh頂点を更新して法線を再計算する。今回のUnity実装では、重み付きフィッティングまでは採用せず、既存のPoly6カーネルと空間グリッドを利用する単純な重み付き平均を採用した。
